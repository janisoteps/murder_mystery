# Season 3 spoiler-safe review protocol — *The Winter Garden*

> PRIVATE PRODUCTION FILE. This protects a player who is also directing development. Do not reveal final evidence placement, clue density, concealed relationships, final interaction IDs, or hidden asset names during review.

## Purpose

The user must be able to inspect and direct the investigator, map, NPC visuals, and every 3D location without learning the solution. Geography will inevitably become familiar. Narrative significance should not.

The review environment and actual case must use separate data, state, and content boundaries. A visual disguise alone is insufficient if final clues or NPC knowledge reach the browser.

## Review modes

### Investigator playground

Contains a neutral courtyard/interior loop, ramps, stairs, doorways, occluders, different surface materials, close/medium/far isometric zoom, and harmless interactions. No Season 3 location, NPC identity, evidence, or case text appears.

Acceptance areas:

- believable anatomy and silhouette at every gameplay zoom;
- locomotion start, stop, turn, idle, and interaction transitions;
- face, hair, hands, footwear, and clothing at close zoom;
- fabric and hair response without exaggerated simulation;
- camera collision/occlusion and wall cutaway behavior;
- selection, navigation, and interaction reach;
- performance at the intended detail level, assessed by the user running the app.

### Location review

Uses the approved floor plan and final environmental art direction, with neutral sample content. The user can walk every route, test zoom, operate systems, inspect object readability, and assess atmosphere.

It does not include final evidence locations, fatal positions, discovered-text content, suspect-specific behavior, or actual clue counts per room.

### NPC visual review

Uses public identity, occupation, appearance, ordinary demeanor, and a neutral animation/action. It omits guilt, complicity, injuries, concealed fear, private relationship, evidence possession, and directions to look suspicious.

### Dialogue behavior review

Uses invented support characters and a non-case scenario with the final pipeline. It tests distinct voices, memory, clarification, small talk, evidence-versus-claim handling, and refusal behavior without importing the Season 3 knowledge base.

## Floor-plan review rules

Player-facing floor plans may label:

- room functions;
- entrances, exits, stairs, and circulation;
- windows, light direction, elevation, and camera zones;
- major furniture and architectural systems;
- ordinary ambient activity zones;
- interaction classes such as door, drawer, machine, seating, or inspection surface.

They must omit:

- true crime scene labels and body route;
- final clue and witness positions;
- concealed access or story gates;
- suspect names attached to private spaces unless publicly obvious;
- final interaction IDs;
- intended misdirection and return-state purpose.

## Detail parity

Production attention itself can spoil a mystery. Therefore:

- every flagship room receives ordinary props and at least two meaningful non-case interactions;
- final clue objects do not receive uniquely bright material, animation, sound, or camera framing before discovery;
- the true scene is not the only room with bespoke systems;
- neutral objects use the same modal quality and interaction polish as evidence;
- locked doors communicate ordinary access reason, not hidden narrative importance;
- final evidence density differs from review content and cannot be inferred from sample placement.

## Review permutations

Each location review fixture should support at least two neutral content arrangements. Sample objects move among plausible surfaces, NPC stand-ins change ordinary routes, and interaction prompts cover the same technical cases without mirroring final placements.

Permutations are chosen independently of the final case overlay. They must not use a simple offset or renamed version of final clue coordinates.

## Data isolation

Recommended later structure:

- public base environment: geometry, neutral materials, architecture, lighting, ambience, collision, ordinary interactions;
- review fixture: substitute object definitions, neutral text/images, test NPCs, and independent save state;
- server-private case overlay: hidden interaction activation, evidence definitions, NPC knowledge, clue conditions, event rules, and final positions;
- discovered public delivery: only content already revealed to this save.

The browser must never download the complete case overlay, undiscovered evidence manifest, future dialogue nodes, proof evaluator, or private filenames. Obscured JavaScript, hidden DOM, CSS visibility, and predictable asset URLs are not protection.

## Asset naming and release

Public environment assets use neutral architectural names. Private evidence assets use opaque internal identifiers outside public asset directories until discovered delivery is implemented. Do not encode culprit names, “murder weapon,” “true scene,” or proof-group labels in browser-visible requests.

Externally generated review images contain neutral documents, objects, and photographs. The user should never be asked to generate the final incriminating text, damaged garment, weapon state, or concealed comparison before playing.

When actual evidence art must eventually be produced, use a private generation workflow that does not display prompts or results in the user's normal task. If no such workflow is available, redesign the evidence to use procedural/private compositing or postpone that asset rather than expose it.

## Scene implementation sequence

1. Approve spoiler-safe floor plan.
2. Build architectural shell, camera behavior, navigation, and wall cutaways.
3. Add materials, lighting, sound, weather, and ambient motion.
4. Add ordinary systems and neutral review permutations.
5. User reviews and requests changes.
6. Freeze reviewed public base contract.
7. Add private case overlay without opening or previewing it to the user.
8. Verify data isolation through static inspection and the user's eventual play workflow, subject to the global instruction that only the user runs the app.

Do not place final evidence during early visual iteration. Geometry changes should not repeatedly expose narrative overlays.

## What progress updates may say

Safe updates may report that a location base, zoom behavior, interaction class, ambience layer, or private overlay stage is complete. They may describe public room use and visual character.

Updates must not say which room is narratively central, how many real clues it contains, which NPC visits privately, why a return matters, or whether an ordinary object is evidence.

## User screenshots and feedback

When the user runs review mode and shares observations, treat visible sample content as neutral. Never confirm whether it resembles final placement. Fix visual and interaction issues in the public base or review fixture without discussing private overlay effects.

## Final safeguard

Before the actual season is playable, confirm that the review route, development logs exposed to the user, public manifests, browser network payloads, and asset names contain no solution-bearing content. This is a future verification task. It must respect the standing rule that Codex does not run the application, builds, or tests.
